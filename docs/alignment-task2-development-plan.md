# Alignment 任务二：四问分析与证据验证开发计划

日期：2026-10-23。首阶段只使用本地合成结果，不下载科研数据、模型、远程样例或镜像。

2026-11-02 开发更新：已编写真实服务器后端、派生分析 packet 和显式 `--allow-real` 接口，见 [服务器运行说明](../tasks/alignment/SERVER_RUNBOOK.md)。本地仅做静态检查，不运行测试；真实任务及修改后的回归用例需在服务器验证。真实分析先按 story 保留确认材料，再在开发部分拟合和选层，使用逐受试者的 pooled held-out Pearson 汇总，单独命名协议，不宣称等于官方完整数据 benchmark 总分。

## 1. 已确定的任务边界

任务二评价 Agent 使用可靠 alignment 工具分析证据并控制结论强度的能力。任务一负责实现和复现计算；任务二复用计算结果，不重复要求编写回归流程。

四个固定问题：

1. 整体形态是什么？哪些层分数较高，是否存在峰值、平台或多个高点？
2. 差异有多大、证据有多强？最佳层相对最后层或预设基线的优势是否得到支持？
3. 群体选层是否代表各受试者？报告个人最高/近优层、群体层距个人最高分的差距，并逐一移除受试者检查选层敏感性。
4. 选层结论能否在未参与选择的新材料上复现？固定层后，比较同一批受试者在确认材料上的基线优势及近优程度；没有确认材料明确报告未评价。

开放分析顺序、补充实验和报告表述；固定数据身份、测量协议、必答问题与证据要求。不奖励固定模型分数高，也不要求每个实例都存在唯一最优层。初版允许查看完整开发层曲线，不用随意限次制造难度。

## 2. 两阶段范围

| 当前离线脚手架 | 后续真实任务 |
|---|---|
| 本地生成逐层/受试者/刺激块分数表 | 接入经任务一验收的特征、预测及 Brain-Score 结果 |
| 描述性形态、配对差值、个人近优差距及逐人移除敏感性 | 校准有科学意义的效应阈值及不确定性分析 |
| 同一批合成受试者的新材料、先提交再揭示 | 同受试者独立材料；分别检查基线优势保持与距最佳观测值的差距 |
| 最小 stdio MCP 子集和可信端日志重放 | Agent host 接线、权限隔离、完整互操作验收 |
| 结构化四问答案核验 | 真实实例、专家参考和 Agent 区分能力评估 |

首阶段不实现真实模型推理、统计显著性、等价性检验或真实 OOD 结论。合成工程规则与未来科学协议使用不同版本。

## 3. 测量及统计口径

- 层曲线是对相关候选表示的描述，不将层数作为独立样本量。
- 同一输入重复计算属于复现性；跨受试者/材料变化才涉及相应稳定性。
- Q3 只描述已观察受试者，不预设个体差异小；逐人移除是敏感性分析，不是留出受试者泛化。未发现单人影响不能排除多人共同影响。
- Q4 固定受试者，只变材料；按完整 passage/story 等单位划分并避免上下文泄漏。新材料不自动构成 OOD。缺确认材料的案例仅检验证据边界意识。
- 最高点不自动意味着可靠优势；缺乏差异证据不等于已证明等价。
- OOD/分布变化由明确的材料、受试者等元数据定义，不由孤立高分判断。
- 真实统计方法需先确定推断对象，再匹配重采样单位；不能把交叉验证折当独立受试者。
- 选层后的确认与开发阶段探索分开；确认测试响应不得参与选层、读出拟合或调参。若在独立的确认训练部分重新拟合读出，须明确迁移的是层配置。
- 若沿用官方数据而改变拆分/聚合，使用独立 profile，不声称与官网综合分等价。

## 4. 输入、工具和证据契约

首版 packet 包含：层顺序、基线层、来源 dataset ID、确认 dataset ID 或 null、材料变化描述，以及按 subject/block/layer 标识的分数表。确认集的 subject 集合必须相同、block 集合必须不相交；不接受改换受试者的确认集。模型、特征、metric 和数据版本在真实后端增加并冻结。

服务接口：

| 工具 | 输入 | 返回 |
|---|---|---|
| describe | 无 | 可用层、协议、单位、确认材料是否存在 |
| profile | 开发 dataset ID | 全层均值、受试者/刺激块明细和覆盖情况 |
| compare | 两个层 ID | 配对差异；不自动作机制解释 |
| stability | 层 ID | 各受试者最高/近优层、分差、成员比例，及逐人移除后的最高/近优层和原选层分差 |
| commit_selection | 层 ID | 冻结配置，重启后仍不能更改 |
| generalization | 无 | 固定层在开发/确认材料上的基线差值、差值变化、确认分数及距最高观测分数的差距，或 not_evaluated |

每个成功调用返回 run_id、输入包哈希和结构化结果。服务在维护者目录记录工具、参数、结果和哈希链；评分器从维护者配置的路径读取日志并重新计算，不信任提交文件中的日志路径。哈希链只保证一致性，不提供身份认证；真实验收必须有操作系统/容器权限边界。

## 5. 输出与评分

提交 answers.json 与 report.md。四个答案分别携带结构化事实、结论状态及 evidence run IDs。语句可以不同；集合字段顺序不影响评分。没有确认数据时，not_evaluated 是正确答案；有数据却不进行规定验证不能借此获得满分。

当前任务版本 0.2，profile 为 synthetic-profile-descriptive-v2，答案 schema 为 bpb-profile-answers/2。Q3 分开报告个体代表性和单人移除敏感性；平台内最高层号变化不算超过近优阈值的变化。Q4 分开报告基线优势保持/消失/反转/开发阶段无优势，以及确认集近优状态，不能互相替代。旧版本上下文和答案拒绝复用。

离线主指标 profile_analysis_success：四问均通过取 1，否则取 0。辅助 four_question_score：通过问题数 / 4。低 brain score 不会降低正确分析的得分。数字、结论状态、数据范围、证据类型和参数全部核验；报告自由文本暂留作人工审阅，未自动评分或认证。

错误答案是可评价失败；缺必需文件/问题是 submission_invalid；维护者输入或日志损坏是 scoring_failed。没有做必要工具调用属于任务失败，不能归为基础设施缺失。

真实版本另行设计结论校准和确认性指标。开放发现可盲审，不将文风或未经核验的“洞见”混入主分数。

## 6. 开发阶段与验收

### P0：冻结四问协议

交付：题面、字段说明、schema、描述性规则、范围与失败语义。验收：各问题能明确区分计算事实、描述性判断和未经执行的验证。

### P1：离线 profile 后端

交付：本地 fixture 生成器和分析函数。九种场景覆盖峰值、平台、受试者分歧、单个受试者主导、材料排序变化、基线优势消失、基线优势反转、无确认材料和平分数。验收：手算个体差距/逐人移除/确认配对差值、平台内层号变化、行序不变性、数据身份与非有限值检查。所有结果实际从输入计算，不能只返回场景标签。

### P2：MCP 与证据链

交付：独立工具 core、stdio 适配、输入输出 schema、日志重放和选择冻结。验收：初始化、列工具、调用、错误响应、重启恢复；确认结果不得通过 profile 提前读取。MCP 不替 Agent 返回自然语言科研结论。

### P3：四问评分器

交付：结构化答案核验、证据关联、数字和状态检查、脚本基线。验收：正确参考通过；虚构 run ID、误用比较证据、伪造分数、显著性越界、无数据却主张泛化等被检出。没有确认数据的正确回答必须通过。

### P4：BrainPilotBench 集成

交付：位于 tasks/_example/alignment-profile-synthetic 的示例、prepare/check 脚本和 CLI smoke。验收：prepare → manual → MCP 调用 → resume → verify → score → leaderboard。正式数据未验收，不增加 canonical runnable 数量。

### P5：真实后端（后续）

接入任务一的接受格式并锁定科学版本；测试缓存/原生计算等价性、计时和内存；实现正确的统计程序与独立确认安排。完成前 real backend 明确报未实现，不回退到合成数据。

### P6：真实任务有效性（后续）

构建经过审阅的真实实例；比较完整层遍历+固定统计+模板报告基线与 Agent。重复次数由试跑方差决定。同数据的重排、重采样和多个折不能当作独立科学任务。若脚本覆盖全部情况，将任务定位为基础证据解读，而非开放科研发现。

## 7. 首阶段完成标准

- 四问契约和合法的未评价/证据有限状态明确。
- 合成数据、参考结果均在本地产生，无下载和付费调用。
- 工具调用到结构化答案再到评分的纵向流程通过。
- 数字和证据被客观核验，报告自由文字的未验证范围明确。
- 核心正负测试通过，现有任务未回归。
- 正式数据、科学统计、真实 Agent、权限隔离尚未验证的部分如实记录。
